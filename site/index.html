software-factory

Label an issue factory and stations on GitHub Actions take it from triage to a reviewed, tested pull request. It runs on a Claude subscription, with no API bill.

  1. 1TriageReads the issue and the code, writes acceptance criteria, or asks what's missing.
  2. 2ImplementMakes the smallest change that meets the criteria and opens a draft pull request.
  3. 3ReviewA different model checks the diff against the criteria. Up to two revision rounds.
  4. 4EvidenceRuns the checks and attaches before and after screenshots and a video.
  5. 5GateWaits for CI, fixes red checks, and merges on green where that's allowed.
  6. 6SweepStarts the oldest issue labeled factory:queued every night, so you can queue work from your phone.
  7. 7SyncWhen another pull request lands first and causes a conflict, merges the base branch in and resolves it.

Set it up

  1. 1Install the appInstall the Claude GitHub App on the repository.
  2. 2Save a tokenCreate a subscription token with claude setup-token (Claude Pro or Max) and save it as the repository secret CLAUDE_CODE_OAUTH_TOKEN.
  3. 3Create the labelCreate the factory label. The workflows create the other labels they use.
  4. 4Configure checks (optional)Add .github/factory.json and an executable .github/factory-setup.sh that installs what your checks need. The setup script runs before the implement, revise, evidence, and CI-fix stations.
  5. 5Allow merging (optional)Set the repository variable FACTORY_AUTOMERGE to 1 to let the factory merge green pull requests.

What it costs

Actions minutes are free on public repositories. Claude Code runs on a Claude subscription's OAuth token instead of per-token API billing. Every factory run counts toward that subscription's usage limits.
